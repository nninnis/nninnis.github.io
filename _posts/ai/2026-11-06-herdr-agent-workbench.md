[7월에 Orca를 들이면서](/ai/2026/07/20/orca-ade-dev-environment/) 정착은 조건부라고 썼다. 구려지면 지우고 Ghostty나 PowerShell 7로 돌아간다고. 석 달 남짓 지났고, 결과적으로 그 문장대로 됐다. 지금은 터미널에서 herdr를 띄우고 그 안에서 에이전트를 돌린다. 어쩌다 그렇게 됐는지, 그리고 왜 이 구성이 당분간 안 바뀔 것 같은지 정리한다.

---

## 애초에 찾던 건 작업대였다

돌이켜 보면 내가 필요했던 건 병렬 오케스트레이션 도구가 아니었다. 클로드 코드와 코덱스를 올려놓고 일할 작업대, 조금 거칠게 말하면 셸이었다. 조건을 적어 보면 여섯 개다.

- 클로드 코드와 코덱스를 한 화면에서. 특정 벤더 앱에 묶이지 않을 것
- 에이전트를 상시 띄워 두고, 프로젝트별로 지금 뭘 하고 있는지 실시간으로 보일 것
- 프로젝트 간 전환이 빠를 것
- 윈도우 데스크톱, 맥북, 업무용 윈도우 노트북 세 대에서 같은 경험일 것
- 가벼울 것
- 세션과 폴더가 지저분해지지 않을 것

마지막 조건은 처음부터 적어둔 게 아니라 Orca를 쓰면서 추가된 것이다.

## 떨어져 나간 것들

| 후보 | 탈락 이유 |
|---|---|
| Claude, Codex 데스크톱 앱 | 벤더에 묶인다. 프로젝트를 여러 개 오갈 때 불편하다 |
| Cursor, VS Code | 자체 에이전트를 안 쓰면 무거운 에디터일 뿐이다. 에이전트 상태를 한눈에 볼 수 없다 |
| Orca | 조건을 가장 많이 채웠지만 워크트리가 강제된다. 아래에 따로 적는다 |
| 그 밖의 것들 | Paradev, Conductor, Agentastic은 맥 전용. Emdash, Nimbalyst, Kepler는 내장 브라우저가 없거나, 설계 노트 성격이거나, 유료에 GitKraken 종속 |

Orca를 지운 이유는 둘이다. 하나는 무게다. 데스크톱과 맥북에서는 괜찮았는데, 회사 일을 하는 사내 VDI 안에서는 켤 때마다 버벅였다. 노트북 성능 문제가 아니라 VDI 환경에서 무거운 앱이 버티지 못한 것이다. 다른 하나는 태스크 하나마다 git worktree를 만드는 구조다. 7월 글에서 핵심 설계라고 소개했던 바로 그 부분인데, 혼자 순차적으로 일하는 사람한테는 필요 없는 기능이 강제로 붙어 있는 셈이었다. 작업할 때마다 폴더가 쪼개지고, 정리하려고 그 폴더를 지우면 클로드 코드 세션이 이미 사라진 경로를 가리키면서 꼬인다. 조건 여섯 개 중 마지막 둘이 걸렸다.

## 워크트리는 언제 필요한가

워크트리를 두고 한참 생각했다. 결론부터 적으면, 같은 레포를 폴더 두 개로 동시에 열어두는 기능이고, 이게 필요한 상황은 꽤 좁다. 혼자서, 같은 레포에서, 에이전트가 돌고 있는 중에, 추가 작업이 생겼는데, 돌고 있는 걸 멈추면 안 될 때. 이 다섯 가지가 전부 겹쳐야 한다.

내 상황은 어느 쪽도 아니다. 회사 프로젝트에서는 팀 안에서 내 파트를 맡고 있고, 브랜치를 따서 올리면 머지는 다른 사람이 한다. 개인 프로젝트는 한 번에 하나씩 한다. 그리고 워크트리는 2015년에 나온 git 2.5부터 있던 기능이다. 정말 필요한 날이 오면 `git worktree add` 한 줄이면 된다. 도구가 매번 만들어 줄 이유가 없다.

## herdr가 남은 이유

[herdr](https://herdr.dev)는 Rust로 만든 터미널 멀티플렉서다. tmux처럼 pane과 탭, 세션이 있는데, 처음부터 AI 코딩 에이전트를 여러 개 돌리는 용도로 설계됐다. 남은 이유는 조건 여섯 개를 거꾸로 읽으면 된다.

- 워크트리를 만들지 않는다. 폴더도 세션도 쪼개지지 않는다.
- 클로드 코드와 코덱스 세션을 세션 ID 기준으로 복원한다. herdr를 재시작해도 에이전트 세션이 꼬이지 않는다.
- 사이드바에 pane마다 에이전트 상태가 뜬다. 막혀서 입력을 기다리는지, 작업 중인지, 끝났는지가 프로젝트별로 한눈에 보이고, 주의가 필요한 pane으로 바로 넘어갈 수 있다.
- 가볍고, 윈도우와 맥에서 같다.

몇 달 쓰면서 크게 불편한 일이 없었다는 게 사실 가장 큰 이유다.

## 모자란 건 터미널 도구로 메운다

herdr는 에디터도 파일 탐색기도 아니다. 한 창에 전부 모아놓은 느낌은 포기하는 대신, 빠진 자리는 가벼운 터미널 도구로 채웠다.

| 필요한 것 | 채운 것 |
|---|---|
| 폴더 구조 | yazi |
| diff | lazygit |
| 브라우저 | 코덱스 데스크톱 앱에 있는 내장 브라우저가 herdr에는 없다. Playwright MCP를 붙여서 에이전트가 브라우저를 직접 열고 확인한다 |
| 아이콘 | Nerd Font |
| 스크린샷 | 윈도우 herdr는 이미지 붙여넣기가 안 돼서 파일로 저장하고 경로를 넘긴다 |

윈도우에서 yazi를 쓸 때 하나 걸리는 게 있다. scoop으로 깐 `file` 명령이 `-L` 옵션을 지원하지 않아서, Git에 딸려온 것으로 바꿔야 미리보기가 제대로 나온다.

## 남은 한계

- 윈도우 버전은 아직 베타다. 유닉스 PTY가 아니라 ConPTY 위에서 돌아가고, 리눅스와 맥의 기능이 전부 똑같이 지원된다고 약속하지는 않는다.
- 이미지 붙여넣기. 맥에서는 Ghostty에서 kitty graphics 실험 플래그를 켜면 되는데, 윈도우에서는 아직 검증되지 않았다.
- 에이전트 상태 감지가 화면 출력 패턴에 기대는 부분이 있어서 가끔 틀린다. 공식 통합을 설치하면 에이전트가 상태를 직접 알려줘서 많이 줄어든다.

## 지금 구성

7월 글과 비교하면 달라진 건 둘이다. Orca 자리에 herdr가 들어갔고, 회사 구성에 남겨뒀던 로컬 서버용 인텔리제이 폴백이 사라졌다. 코드 리뷰도 서버 띄우는 것도 에이전트에게 시키다 보니 인텔리제이는 디스크 용량만 차지하고 있었다.

| 어디서 | 뭘로 |
|---|---|
| 집, 맥북 | Zed + Ghostty + herdr. TV 보면서 가볍게 할 때는 클로드 데스크톱 앱 |
| 집, 윈도우 데스크톱 | 거의 herdr |
| 회사, 윈도우 노트북 (사내 VDI) | Zed + PowerShell 7 + herdr |

회사 쪽은 중간에 한 단계가 더 있었다. 9월에 새 프로젝트에 들어가면서 에이전트가 코덱스로 정해졌고, Orca가 사내 VDI 안에서 유독 버벅인 탓에 한동안은 코덱스 데스크톱 앱으로 일했다. 그러다 herdr로 옮겼고, 앱에 있던 내장 브라우저 자리는 Playwright MCP로 메웠다.

이 글 같은 건 모바일 앱에서 바로 써서 올리기도 한다.

남은 것들을 나란히 놓고 보면 기준은 하나였다. 가볍고, 빠르고, 번거롭지 않을 것. 한 창에 다 모아놓은 느낌은 그 기준과 맞바꿨다. 다른 사람한테도 맞는 구성인지는 모르겠다. 내 기준으로는 지금까지 써본 것 중 가장 효율이 좋다.
